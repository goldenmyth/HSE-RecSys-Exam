# sweet.tv TV programme recommender

An individual recommendation project for the [exam assignment](exam_quiz_FKN.md) and the [Kaggle competition](https://www.kaggle.com/competitions/sweettv-tv-program-recommender). The task is to rank five programme IDs for each of 1,260 users from historical viewing intervals and broadcast schedules.

The designated final file is [submission_v4.csv](submission_v4.csv), generated by a HistGradientBoosting (HGB) reranker over PPR, ALS, content-based, Repeat, and popularity candidates. It contains 1,260 users in the original template order and five distinct programme IDs per row.

## Evaluation protocol

All boundaries below are half-open intervals in the original calendar labels:

| Stage | Training window | Evaluation or forecast window |
| --- | --- | --- |
| Main validation | 2020-03-09 to 2020-05-18 | 2020-05-18 to 2020-07-27 |
| Earlier check / HGB meta-training snapshot | 2020-03-09 to 2020-04-13 | 2020-04-13 to 2020-05-18 |
| Final fit | 2020-03-09 to 2020-07-27 | 2020-07-27 to 2020-10-19 |

The primary population is the same 1,260 template users, including users with empty relevance or no training history. User IDs remain strings, including 20-digit values. Recommendations of previously watched programmes are allowed.

AP@5 is the sum of precision at relevant recommendation ranks, divided by `min(5, number of unique relevant programmes)`. Empty relevance gives AP=0. MAP is the mean over the complete population. A duplicate prediction occupies its position but cannot score twice; generated lists must contain five distinct positive candidate IDs.

Candidate pools contain positive-duration, labelled airings intersecting the forecast window: **6,384** items for main validation, **4,412** for the earlier check, and **6,649** for the final test window. Calendar overlap is used across schedule-file boundaries. Ground truth is never filtered to training items or to model-scoreable items.

### Viewing definition

- Join `vsetv_id` to `channel_id` and use half-open interval intersections. Apply the verified one-hour clock-gap normalization around 2020-03-29 to both sources; no absolute timezone or UTC conversion is asserted.
- Preserve original viewing rows as separate sittings and remove exact duplicates. Cut rows at the period boundary, remove simultaneous different-channel intervals, and evaluate each remaining continuous piece separately. Separate rows or fragments cannot accumulate to pass the threshold.
- The strict target is **more than 80% of the full canonical programme airing**. The strict50 model fits use **more than 50%**. Equality does not qualify. Zero programme IDs and conflicting schedule intervals do not produce item interactions.
- Deduplicate qualifying user/channel/airing events, then union accepted seconds. The shared fallback retains the earlier **at-least-60-second** interaction rule and ranks programmes by distinct training users. Each window has its own training-only fallback; the earlier check never reuses the main-window popularity fit.

The strict label follows a participant's [methodology description](https://medium.com/data-science/two-layered-recommender-system-methodology-a-prize-winning-solution-c4bdb815b156), not verified Kaggle judge code. Device IDs and actual channel switches are unavailable, so concurrency exclusion is a conservative assumption. Row-only sensitivity is recorded in [strict experiments](results/strict_experiments.json).

## Results on the same strict target

All main scores below use the unchanged >80% relevance, full 1,260-user population, and main candidate pool. The model names identify their training signal.

| Method | Main MAP@5 | Earlier MAP@5 |
| --- | ---: | ---: |
| Unique-user popularity, legacy 60-second history | 0.432098325 | — |
| Repeat50 | 0.502007937 | — |
| Repeat80 | 0.482689374 | — |
| Implicit ALS, strict50 history, 16 factors | 0.337697531 | — |
| Content-based, strict50 history, extended features | 0.237527557 | — |
| PPR, strict50 history, 50 neighbours, restart 0.30 | 0.517427690 | 0.499021605 |
| V3: PPR plus availability adjustment | 0.524651455 | 0.505046958 |
| Historical rejected graph variant: 100-neighbour PPR | 0.527528219 | 0.502405644 |
| HGB A: 15 algorithm features | 0.535281526 | Training target |
| HGB B: A + 7 history features | 0.547428792 | Training target |
| HGB C: B + 6 time features | 0.548394180 | Training target |
| **V4 / HGB D: C + 5 channel features** | **0.552324074** | **Training target** |

ALS uses implicit count confidence; the listed refit has 16 factors, regularization 0.1, confidence `1 + 10 * log1p(watch_count)`, and 20 iterations. CBF uses train-only category, genre, production-decade, director, and actor tokens with TF-IDF item vectors and log-count-weighted user profiles.

The V3 graph uses cosine co-view edges after user-degree normalization, at most 50 outgoing neighbours, log-count personal restart weights, and restart probability 0.30. On its native Top-100, scores receive a bounded multiplier `1 + 0.25 * availability`, where availability is normalized `log1p` forecast airing count. This uses schedule IDs, channels, times, and durations, without future viewing behaviour or future content attributes. The adjusted values are ranking scores, not calibrated watch probabilities.

Before HGB, a separate graph-complement investigation required a main gain of at least 0.005 with a positive descriptive bootstrap lower bound and a nonnegative earlier-window gain. Its best variant gained only 0.002876764 on main and lost 0.002641314 on early, so that investigation produced no submission. The later HGB experiment is a different, successful stage and produced the final V4.

### HGB reranking and temporal fitting

HGB reranks exactly 200 candidates per user. Candidate generation preserves the V3 Top-5, includes its native Top-100, and interleaves additional Repeat, ALS, CBF, and popularity items without consulting relevance. The four configurations above are fixed cumulative feature ablations, not a hyperparameter search. D uses 33 numeric features: 15 algorithm and schedule-exposure features, 7 historical-activity features, 6 time-affinity features, and 5 channel-affinity features.

For the reported main validation scores, base models and features for HGB fitting use only **2020-03-09 to 2020-04-13** history; their >80% targets cover **2020-04-13 to 2020-05-18**. HGB fits 933,000 candidate pairs from 4,665 past-defined users, including 32,977 positives. Main predictions use base models and features fitted from history ending **2020-05-18**. Targets from **2020-05-18 to 2020-07-27** are used for evaluation and selection, never for fitting those evaluated HGB models. An earlier-window HGB test score is therefore not reported: that target window trains the reranker.

The fixed classifier uses 100 iterations, learning rate 0.08, at most 15 leaves, depth 4, minimum leaf size 100, L2 regularization 10, 128 histogram bins, balanced class weights, seed 42, and no internal early stopping. D gains **0.027672619** over V3, with a descriptive paired-bootstrap 95% interval of **[0.020713046, 0.034598765]**, passing the predeclared gain threshold of 0.01 and positive lower-bound requirement. Balanced-class outputs are ranking scores, not calibrated watch probabilities.

Only after selection, the final fit reuses the actual saved early and main out-of-time feature snapshots at their original cutoffs. Their disjoint target windows end by **2020-07-27** and provide **1,892,200 pairs, including 81,117 positives**. Historical features are not regenerated from expanded history. Final base models and prediction features use all available past viewing history **2020-03-09 to 2020-07-27**, with schedule-only forecast exposure through **2020-10-19** and no future viewing labels. The four final cold users retain the shared training-only popularity fallback. The offline score **0.552324074** describes the selected D model before this final refit; the submitted V4's separately returned Kaggle private score is **0.42216**.

The historical popularity score of **0.794783069** used the earlier 60-second relevance definition and is not comparable to this table. Strict main relevance contains 30,172 user–programme pairs, versus 229,906 under that earlier definition.

Full evidence: [original model comparison](results/model_comparison.json), [strict experiments](results/strict_experiments.json), [V3 refinement](results/ppr_refinement.json), [historical graph-complement evaluation](results/ppr_complement.json), [HGB ablations](results/hgb_experiments.json), and [final V4 generation](results/submission_v4_hgb.json). The same two users are used for examples across methods: `11595812149006555679` and `8150816946177670084`.

The earlier window served as a temporal robustness check for the earlier experiments and later became HGB training targets; it is not an independent HGB test. Main validation was reused across experiments, so bootstrap intervals are descriptive and do not correct for repeated model selection. Target horizons increase from 35 days for HGB training to 70 days for main validation and 84 days for final forecasting. Only 10.8% of rows in the first schedule carry a nonzero programme ID. Missing interactions do not establish that a user never watched an item or disliked it. PPR cannot score programmes absent from its training graph, while the final reranker is limited to its generated candidate set.

## Staged reproduction

Execute these commands **only in the isolated checkout**, from its root. They reproduce the historical dependencies as well as the final pipeline and may overwrite that checkout's recorded artifacts. Individual runners stop when prerequisite hashes, period checks, or model checks fail; do not bypass those checks or edit expected hashes.

```bash
# Historical preparation and baseline/model comparisons.
.venv/bin/python -B scripts/prepare_interactions.py
.venv/bin/python -B scripts/evaluate_popularity.py
.venv/bin/python -B scripts/compare_models.py
.venv/bin/python -B scripts/build_submission.py

# Strict single-session labels, model comparisons, and final-fit prerequisites.
.venv/bin/python -B scripts/strict_experiments.py
.venv/bin/python -B scripts/build_submission_v2.py

# Context collection and the selected V3 pipeline.
.venv/bin/python -B scripts/prepare_history_context.py --mode development
.venv/bin/python -B scripts/refine_ppr.py
.venv/bin/python -B scripts/refine_ppr.py --final

# Four fixed HGB ablations, followed by the selected final fit if its gate passes.
.venv/bin/python -B scripts/experiment_hgb.py
.venv/bin/python -B scripts/experiment_hgb.py --final
```

The V3 final command writes `submission_v3.csv` and creates the full-window context prerequisites. The last command writes **`submission_v4.csv` only if the recorded HGB gate passes**. It requires unchanged code, unchanged inputs, and the actual early/main snapshots saved by the immediately preceding HGB experiment in the same checkout. Missing or changed historical snapshots cause failure instead of historical feature regeneration; do not delete caches between these commands or bypass the guards. Final prediction features use full-window history rather than adding split aggregates. Scripts generate local files; they do not upload submissions to Kaggle.

To reproduce the optional historical graph-complement investigation, which produced no submission:

```bash
.venv/bin/python -B scripts/complement_ppr.py
```

Tests can be run separately with `.venv/bin/python -B -m unittest discover -s tests -v`. Recorded JSONs contain configuration, timing, convergence, and audit information; measured runtime depends on the machine and whether preparation caches are reused.
